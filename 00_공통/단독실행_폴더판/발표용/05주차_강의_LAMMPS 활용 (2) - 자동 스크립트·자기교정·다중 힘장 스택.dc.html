5-1 · STAGE 1 · COMPOSITION SPEC

조성 명세 — 사람이 결정하는 값의 선언

역할 실험자가 정하는 값만 한 파일에 모아 물리적 성립 여부 검증 · 파일 경로 · 원자 수 · 스텝 수처럼 계산으로 얻는 값은 기재 금지
spec.yaml
binder: A composition: { saturate: 15, aromatic: 45, resin: 25, asphaltene: 15 } # wt%, 합 100 additive: { name: SBS, wt: 3 } temperatures: [298, 333, 373] # K tier: screening seeds: 3
필드는 단위와 함께 · 주석으로 허용 범위 기록
필수 필드
binder · composition(wt%) · additive · temperatures · tier · seeds — 이 여섯 개로 실행 목록 결정
검증(validation)
조성 합 100 · 온도는 Tg 이상 · 티어별 허용 원자 수 — 하나라도 어긋나면 생성을 시작하지 않고 중단
전개(expansion)
온도 3 × 시드 3 의 곱집합(Cartesian product)으로 9개 실행 — 명세 한 줄 추가 시 실행 수가 곱으로 증가
실패 지점
명세 대신 입력 파일을 직접 수정하면 재현 불가 · 버전 관리 대상은 명세뿐
5-1 · STAGE 2 · TEMPLATE ENGINE

템플릿 엔진 — 값에서 스크립트 문장으로

역할 명세의 값을 자리(placeholder)에 넣어 in.* 스크립트 렌더링(rendering) · 티어 · 앙상블(ensemble) · 힘장 스택에 따른 분기와 반복은 템플릿 담당, 생성기 코드는 값만 전달
in.equil.j2
units real atom_style full read_data {{ data_file }} pair_style hybrid/overlay & {% for p in ff_stack %}{{ p.style }} {% endfor %} velocity all create {{ temp }} {{ seed }} fix eq all npt temp {{ temp }} {{ temp }} 100 iso 1 1 1000 run {{ steps[tier] }}
이중 중괄호는 값 치환 · {% %} 는 반복과 분기
렌더 단위
템플릿 1개 + 값 1벌 = 스크립트 1개 = 실행 1개 · 온도 · 시드마다 별도 파일 생성
분기 처리
티어별 run 길이 · 앙상블 순서(NVT → NPT) · 힘장 개수에 따른 pair_style 하위 스타일 목록을 반복문으로 표현 (pair_style 줄은 1개)
금지 사항
온도 · 스텝 수 · 파일명의 템플릿 직접 기재 금지 — 하드코딩(hard-coding) 시 해당 실행만 경고 없이 달라짐
기록
템플릿 수정 = 방법론 변경 → 템플릿 버전 태그를 실행 기록에 함께 기록
5-1 · STAGE 3 · BUILDER

빌더 — 조성비에서 계산 대상 셀까지

역할 무게비(wt%)를 실제 분자 개수로 환산하고, 3D 좌표 · 결합 목록 · 원자 타입 · 전하를 갖춘 data 파일 생성 · 스크립트가 읽을 계산 대상 자체를 만드는 단계
01 개수 환산
wt% ÷ 분자량 → 몰비 → 목표 원자 수에 맞춘 정수 개수 · 반올림 오차를 조성표에 재기록
02 단분자 구조
SMILES(Simplified Molecular Input Line Entry System) → RDKit 3D 임베딩(embedding) · 간단 최적화로 뒤틀린 초기 구조를 제거
03 셀 충전
Packmol로 목표보다 낮은 밀도의 셀에 배치 · 이후 NPT 압축으로 실제 밀도에 도달
04 타이핑
원자 타이핑(atom typing) · 전하 부여 · 결합 · 각 · 이면각 목록 생성 → data 파일
실패 지점
Packmol 수렴 실패 · 타입 누락으로 생기는 결합 항 0 · 겹친 원자로 인한 초기 발산 — 셋 다 첫 스텝 로그에 표시
자동 점검
원자 수 · 총 전하 0 · 최근접 거리 하한 · 목표 조성과의 편차를 빌드 직후 검사 · 통과한 셀만 다음 단계로 전달

5-1 · STAGE 3.2 · GEOMETRY & PACKING

빌더 2 — 단분자 구조와 셀 충전

01 SMILES → 3D
RDKit ETKDG(Experimental-Torsion Knowledge Distance Geometry) 임베딩으로 좌표 생성 · MMFF(Merck Molecular Force Field) 가벼운 최적화로 겹침과 뒤틀림 제거 · 분자당 1개 표본을 pdb로 저장
02 셀 치수 결정
초기 밀도를 목표의 절반(≈ 0.5 g/cm³)으로 잡아 변 120 Å 정입방으로 설정 — 여유 공간이 있어야 배치 수렴
03 배치 · 압축
Packmol로 공간 배치 → 에너지 최소화 → NVT 단시간 → NPT 압축으로 실제 밀도 도달
실패와 재시도
tolerance 2.0 Å 는 원자 간 최소 거리 — 너무 크면 수렴 실패, 너무 작으면 초기 발산 · tolerance를 맞추지 못하면 상자를 5% 넓혔다가 재시도 · 시드만 바꿔 다시 도는 재시도도 자동화 대상
pack.inp · Packmol 입력 (생성된 개수 그대로 입력)
tolerance 2.0 filetype pdb output cell_binderA.pdb structure squalane.pdb number 190 inside box 0. 0. 0. 120. 120. 120. end structure structure dochn.pdb number 591 inside box 0. 0. 0. 120. 120. 120. end structure # resin 241 · asphaltene 139 동일 형식으로 계속
