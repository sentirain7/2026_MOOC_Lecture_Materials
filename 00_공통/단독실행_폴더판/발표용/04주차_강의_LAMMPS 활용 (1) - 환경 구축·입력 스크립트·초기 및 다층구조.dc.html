4-1 · OVERVIEW

LAMMPS의 계산 대상

정의
LAMMPS(Large-scale Atomic/Molecular Massively Parallel Simulator) = 입자에 작용하는 힘으로 Newton 방정식을 적분하는 고전 분자동역학(MD, molecular dynamics) 엔진 — 전자 상태 계산 없이 힘장으로 대체
병렬 구조
공간을 쪼개 프로세스에 나눠 주는 영역 분할(domain decomposition) · MPI(Message Passing Interface)로 수십~수천 코어까지 확장
사용자 인터페이스
GUI(graphical user interface) 없음 — 텍스트 명령 한 줄씩으로 계 정의 · 실행 (in · data · include)
확장 방식
기능은 패키지(package) 단위로 추가 — 빌드 때 포함한 패키지의 명령만 사용 가능

이 강좌가 쓰는 범위 — 유기 분자 벌크와 계면 · GAFF2(General AMBER Force Field 2) 계열 힘장 · NVT/NPT 앙상블(ensemble) · 밀도 · CED(cohesive energy density) · 점도 · 부착일(work of adhesion)

Ubuntu 에서 LAMMPS 설치 — 준비와 CPU 빌드

00 먼저 결정할 것
CPU 전용인가 GPU 를 쓸 것인가 · 필요한 패키지(MOLECULE · KSPACE · RIGID · EXTRA-DUMP) · 정밀도(double 기본) · 버전은 stable 브랜치 고정
GPU 가 없거나 계가 10만 원자 이하면 CPU + MPI 만으로 충분 — 빌드 단순 · 스타일 제약 없음
01 의존성 설치 (apt)
sudo apt update
sudo apt install -y build-essential cmake git \
  python3-dev libopenmpi-dev openmpi-bin \
  libfftw3-dev libjpeg-dev libpng-dev
MPI · FFTW3(고속 푸리에 변환 라이브러리)는 병렬과 kspace(pppm, particle–particle particle–mesh)에 필수 · jpeg · png 는 dump image 용
02 소스 받기 · 빌드 디렉터리
git clone -b stable https://github.com/lammps/lammps.git
cd lammps && mkdir build && cd build
03 CPU 빌드 (cmake)
cmake -D BUILD_MPI=yes -D BUILD_OMP=yes \
  -D PKG_MOLECULE=yes -D PKG_KSPACE=yes \
  -D PKG_RIGID=yes -D PKG_EXTRA-DUMP=yes \
  -D FFT=FFTW3 -D CMAKE_BUILD_TYPE=Release ../cmake
make -j$(nproc)
sudo make install   # lmp 실행 파일 설치
확인 — lmp -h | head 로 컴파일된 패키지 목록 점검
conda 는 어디에 필요한가
LAMMPS 본체는 apt + 소스 빌드가 안정적 · conda 는 주변 파이썬 도구(RDKit · OpenBabel · MDAnalysis · moltemplate · packmol · pandas)를 격리하는 용도
주의 — conda 환경의 openmpi · gcc 가 시스템 것과 섞이면 실행 시 심볼 오류 · LAMMPS 를 돌릴 때는 conda deactivate 또는 MPI 없는 별도 env 사용
동작 확인
cd ../bench
mpirun -np 4 lmp -in in.lj   # 3d LJ melt, 정상 종료 확인

실행 방법 · 정밀도 · 검증

07 실행 방법
# GPU 1장 · MPI 2랭크
mpirun -np 2 lmp -k on g 1 -sf kk \
  -pk kokkos newton on neigh half -in in.run
MPI 랭크(rank) 수는 GPU 장수의 1 ~ 4배 · 랭크 과다 시 GPU 경합으로 속도 저하
정밀도 선택
KOKKOS 는 기본 double · GPU 패키지는 -D GPU_PREC=mixed|double
mixed 는 1.5 ~ 2배 빠르지만 장시간 NVE 에너지 드리프트(energy drift)가 커질 수 있음 → 물성 생산 런은 double, 선별 런은 mixed
주의 · 검증
KOKKOS 가 지원하지 않는 pair · fix 를 쓰면 그 부분만 CPU 로 폴백(fallback) → 성능이 오히려 하락 · 로그의 "(kk)" 표시로 확인
같은 입력을 CPU 와 GPU 로 각 1000 스텝 돌려 초기 에너지 · 압력이 유효숫자 5자리까지 일치하는지 대조
실험 ID 에 빌드 종류(cpu · kk-double · kk-mixed)를 기록 — 정밀도가 다른 결과의 한 데이터셋 혼합 금지
