## 1. 앱 개요

### 1.1 목표
- **입력**: 단순 분자 바인더의 조성, 첨가제 종류와 함량, 계면 물층 두께, 온도
- **계산**: CPU LAMMPS로 **광물 | 물 | 바인더 3층 구조**를 만들고 직접인장(direct tension) 시험을 한다.
- **산출**: 최대 인장응력, 분리일(work of separation), 파괴 위치
- **데이터**: 온도별 약 100개, 총 약 300개 조건의 인장 데이터셋
- **학습과 역설계**: 기계학습 대리모델(surrogate model)과 불확실성을 만들고, 다목적 역설계로 조성을 추천한다.
- **검증**: 추천 조성을 MD로 다시 계산해 폐루프(closed loop)를 1회 이상 돈다.

### 1.2 전제와 한계
- **LAMMPS는 CPU 전용이다.** GPU·KOKKOS 패키지는 쓰지 않고, MPI + OpenMP만 쓴다.
- **바인더는 단순 분자 3~4종의 혼합물이다.** 실제 아스팔트(SARA 수천 종)의 대용 모델이며, 분자마다 SARA 분획의 역할만 대신한다.
- **3층 구조**
  - 하부: α-석영(α-quartz) (001) 수산화 표면, ClayFF, 결정 전체를 고정
  - 중간: 물층, SPC/E
  - 상부: 바인더, GAFF2
- **결정 전체 고정의 근거**: LA 문헌 조사 `docs/ops/LIT_SURVEY_TENSILE_SETUP_20260718.md`. ClayFF 광물 골격은 결합이 없는 비결합 모델이라, 표면을 자유롭게 두면 표면 원자가 떨어져 나간다.
- **인장 속도는 실험보다 수 자릿수 빠르다.** 따라서 절댓값은 실험과 바로 비교하지 않고, 조건 사이의 **상대 경향**(온도 · 물 · 첨가제 효과)만 해석한다.
- **캠페인 도중에는 설정을 바꾸지 않는다**(LA 교훈 14). 인장 속도 · 컷오프 · 셀 크기는 4주차 벤치마크 뒤 고정한다.

### 1.3 공학적 의미
- **물층 0과 물층 있음의 비교**는 수분 손상(moisture damage)의 MD 대응물이다. `MD-TSR = σ_max(물층) / σ_max(건조)`을 인장강도비(TSR, AASHTO T 283)에 대응하는 **상대 지표**로 쓴다.
- **첨가제**로 박리방지제(anti-stripping agent) 계열의 단순 분자를 넣는다. 첨가제가 물층 조건의 부착 저하를 줄이는지를 역설계의 목표로 삼는다.
- **저온(253 K)과 상온(293 K) 비교**로 취성 · 연성 전이 경향을 본다.

### 2.2 3층 셀 기본 치수 (초기 가정, 4주차 벤치마크에서 확정)

| 층 | 두께 | 대략 원자 수 |
|---|---|---|
| 석영 슬래브 (고정, 수산화) | 약 16 Å | 약 1,300 |
| 물층 (0 · 10 · 20 분자/nm²) | 0 · 약 3 · 약 6 Å | 0 · 약 300 · 약 600 |
| 바인더 슬래브 | 약 30 Å | 약 3,500 |

- **총 원자 수**: 약 4,500~5,000개. CPU 한 작업(8코어)에서 돌릴 수 있는 규모다.
- **진공 60 Å**: LA 교훈 8(X1 표준)을 따른다. 인장 중 분리가 생겨도 PPPM이 실패하지 않게 한다.
- **장거리 쿨롱**: `kspace_modify slab 3.0`으로 z 방향 주기 영상을 보정한다.

### 2.3 직접인장 프로토콜
1. 3층 조립 → 최소화
2. 목표 온도에서 NVT 이완(결정 고정, 바인더 상부 자유)
3. 바인더 최상부 5 Å를 그립(grip)으로 지정하고 +z 방향 등속으로 끌어올린다. 석영은 고정한다.
4. 기록: 그립에 걸리는 z 방향 힘 / 단면적 = 응력, 그립 변위, z 밀도 분포(파괴 위치 판정용)
5. 중단 조건: 그립 변위 40 Å, 또는 응력이 최대값의 5 % 아래로 떨어진 뒤 5 Å 더 진행

| 설정 | 값 | 비고 |
|---|---|---|
| 시간 간격 | 2 fs | `fix shake`(X–H 결합, SPC/E 물). 1 fs 대조 실행으로 검증 |
| 힘장 | GAFF2(AM1-BCC) · SPC/E · ClayFF | 교차항은 Lorentz–Berthelot 산술 혼합. 근거: LA `docs/theory/clayff-gaff2-mixing-theory.md` |
| 쌍 상호작용 | `lj/cut/coul/long 12.0`, `pppm 1e-4`, slab | CPU |
| 인장 속도 | 학습용 0.5 Å/ps, 기준 캠페인 0.1 Å/ps (가정) | 4주차 벤치마크 뒤 고정 |
| 온도 | 253 · 273 · 293 K | |

### 2.4 산출 지표 (6주차에서 구현)
- **σ_max**: 최대 인장응력(MPa). 창 평균 곡선에서 구한다.
- **d_peak**: 최대 응력 지점의 그립 변위(Å)
- **W_sep**: 분리일(mJ/m²). 응력–변위 곡선 아래 면적으로 구한다. 식은 LA `src/metrics/tensile_metrics.py`를 참고한다.
- **파괴 위치**: 광물–물, 물–바인더, 바인더 내부(응집 파괴) 중 하나. 최종 프레임의 z 밀도 분포에서 빈 구간이 생긴 위치로 판정한다.
- **MD-TSR**: 같은 조성 · 온도에서 물층 조건 σ_max를 건조 조건 σ_max로 나눈 값
- **보조 특징**: 바인더 벌크 밀도, CED, δ. 강의계획서 6주차 「CED 계산 파이프라인」 항목이다.

## 3. 데이터셋 설계 — 온도별 약 100개

| 요인 | 수준 | 수 |
|---|---|---|
| 바인더 조성 | 4분자 질량분율, 제약 있는 단체(simplex) 위 Sobol 표본 | 12 |
| 첨가제 | 없음 · A · B · C, 함량 2 · 4 wt% | 조성과 결합해 36 조합 |
| 물층 | 0 · 1 · 2 분자층 | 3 |
| 온도 | 253 · 273 · 293 K | 3 |

- **본 캠페인**: 36 조합 × 물층 3 = 온도당 108개. 온도 3개로 **324개**다.
- **반복 실행**: 대표 조건 4개 × 물층 3 × 추가 시드 2 = 온도당 24개, 총 72개. 시드 산포를 추정하는 데 쓴다. LA 교훈 13에 따르면 시드 사이 산포가 크므로 n = 1로 비교하면 판단을 그르친다.
- **조성 ID(comp_id)**: 조성 + 첨가제 조합마다 하나를 준다. 기계학습의 그룹 분할 키다.
- **확장 세트(8주차)**: 기판을 수산화칼슘(portlandite, Ca(OH)₂)(001)으로 바꾼 부분 세트. 12 조합 × 물층 3 × 293 K = 36개
- **추가 실행**: 능동학습 1회분 30개(10주차), 역설계 검증 18개(13주차)

### 계산량 (가정 — 4주차 벤치마크 값으로 교체)

| 단계 | 실행 수 | 한 실행 (가정) | 합계 |
|---|---|---|---|
| 5주차 반복 연구 | 27 | 약 1 h | 약 27 h |
| 7주차 본 캠페인 + 반복 | 324 + 72 | 약 1 h | 약 400 h |
| 8주차 portlandite | 36 | 약 1 h | 약 36 h |
| 10주차 능동학습 | 30 | 약 1 h | 약 30 h |
| 13주차 검증 | 18 | 약 1 h | 약 18 h |
| **합계** | **약 510** | | **약 510 작업·시간** |

- **한 실행 약 1 h의 가정**: 5,000원자, 8코어, 2 fs, 이완 0.2 ns + 인장 0.4 ns(기준 속도 0.1 Å/ps로 40 Å)
- **소요 기간**: 64코어 노드 1대에서 8개를 병렬로 돌리면 약 3일이다.
- **담당 구분**
  - **본 캠페인**: 강의자가 개강 전에 **기준 데이터셋(reference campaign)**으로 계산한다.
  - **수강생**: 학습용 속도(0.5 Å/ps)로 할당된 부분 세트(12~20개)만 계산한다. 자신의 결과를 기준 데이터셋과 비교한다.
- **CPU 운영 규칙**: `OMP_NUM_THREADS`를 명시한다(LA 교훈 28). 32랭크를 넘는 강한 확장(strong scaling)은 효율이 떨어지므로 작은 작업 여러 개를 병렬로 돌린다(교훈 10 · 12).

  - 분자 라이브러리 8종을 GAFF2로 타이핑한다(antechamber · parmchk2, CPU).
  - AM1-BCC 전하를 계산한다(sqm, CPU). 분자 전하 합이 0인지 검사한다.
  - ClayFF 석영 원자 타입과 SPC/E 물 파라미터를 출처와 함께 둔다.
  - **3자 이종쌍(unlike pair) 표**: 바인더–물, 바인더–광물, 물–광물. 조합 규칙(combining rule)을 비교한다.
  - 평형 판정 함수: 블록 평균 · t_eq 판정
- **[앱]** 「분자 라이브러리」 페이지 — 분자 · 전하 · 타입 표
- **완료 기준**: 8종 모두 타이핑과 전하 계산이 끝나고, `pair_coeff` 교차항 표가 생성된다.

### 4주차 · 벌크 → 3층 구조 · CPU 벤치마크
- **[계획서]** LAMMPS 예제 입력 · 다층구조 모델
- **모듈**: `build/`
  - 조성(wt%)을 분자 개수로 환산한 뒤 Packmol로 충전한다(초기 밀도 낮게, 실패 시 시드 변경).
  - 벌크 바인더 NPT 평형화(최소화 → 어닐링 → 293 K NPT). 평형 밀도를 평균 ± SE로 보고하고 문헌값과 비교한다(11주차에 보강).
  - α-석영(001) 슬래브를 COD CIF에서 자르고 표면을 수산화한다. 참고: LA `docs/workflows/crystal-slab-hydroxylation-procedure.md`
  - 물층: 목표 분자층 수에 맞는 물 분자 수를 계산해 슬래브 위 구간에 Packmol로 충전한다.
  - 3층 조립: 석영 | 물 | 바인더, 진공 60 Å. 원자 타입 번호가 겹치지 않게 병합하고 z 순서를 검사한다.
  - **CPU 벤치마크**: 4 · 8 · 16코어의 ns/day와 1 fs · 2 fs를 비교한다. 결과로 §3 계산량 표를 교체하고, 인장 속도 · 코어 수를 **확정**한다.
  - 수동 직접인장 1회(기준 조성 · 물층 1 · 293 K)
- **[앱]** 「구조 빌더」 페이지 — 조성과 물층을 고르면 3층 셀 스냅샷과 원자 수를 보여 준다.
- **완료 기준**: 3층 셀 data 파일, 벤치마크 표, 첫 3층 인장 곡선 1개

### 5주차 · 생성기 · 실행기 · 자기교정 · 반복 연구
- **[계획서]** LAMMPS 자동 생성기 · 다중 힘장 예제
- **모듈**: `gen/`
  - `spec.yaml`(조성 · 첨가제 · 물층 · 온도 · 시드 · 속도) → 실행 패키지(`in.*` · `data.*` · `ff.inc` · manifest)를 만든다. Jinja2 템플릿이고 값은 하드코딩하지 않는다.

  - **실행 대장**: `runs.sqlite` 한 테이블(exp_id · spec · 상태 · 경로 · 시간)
  - **반복 연구**: 기준 조성 × 물층 3 × 온도 3 × 시드 3 = 27개 실행

- **완료 기준**: 27개 실행이 사람 개입 없이 끝나거나, 실패 원인이 분류된다.

### 7주차 · 설계 공간과 본 캠페인
- **[계획서]** 아스팔트 분자구조(SARA · 첨가제) · 모델 빌드 · 다중 힘장 입력

- **완료 기준**: 기준 데이터셋 약 400행이 실행 대장에 적재되고, 1차 경향 그림이 나온다.

### 9주차 · 대리모델 1 — XGBoost + SHAP

## 8. 종속성 설치 계획 — 차시와 함께 설치

### 8.1 원칙
- **차시 연동은 권장이며 필수가 아니다.** 아래 표는 도구를 처음 쓰는 차시를 권장 시점으로 적은 것이다. 설치는 `install/` 의 그룹(G0~G5, `PROMPTS_STRUCTURE.md` S0)으로 언제든 한 번에 할 수 있다. 앱을 만드는 프롬프트는 `PROMPTS_APP.md`, 데이터용 구조를 만드는 프롬프트는 `PROMPTS_STRUCTURE.md`에 있다.
- **LAMMPS는 conda-forge 안정판 2025.07.22(stable 22Jul2025) CPU 빌드를 기본으로 쓴다.** 필요한 패키지(ML-SNAP 포함)가 모두 들어 있어 소스 빌드가 필요 없다. 4-1에서는 선택 실습으로 `stable_22Jul2025_update6` 소스를 CMake로 빌드해 패키지 구조를 익힌다. 버전 · 빌드 선택 근거는 `INSTALL_GUIDE.md` §1.
- **Packmol은 conda-forge 21.2.1(미리 컴파일된 판)이 기본이다.** 소스 컴파일(21.2.3, CMake)은 선택이다. 성공 판정은 종료 코드 · `Success!` · 거리 위반 · 원자 수를 모두 확인한다(`INSTALL_GUIDE.md` §6).
- **힘장 조합은 `FF_COMPATIBILITY.md`를 따른다.** GAFF2(AM1-BCC) · SPC/E · ClayFF이고, 타입 접두어는 g2_ · sw_ · cf_, 검증은 V1~V9다.
- **Windows는 WSL2에서만 진행한다.** 주의 사항은 `INSTALL_GUIDE.md` §4에 있다.
- **CPU 전용**이다. GPU · KOKKOS는 4-1에서 개념만 설명하고 빌드하지 않는다.
- **환경 하나(`dtlab`)가 주차마다 자란다.** 차시별 설치 스크립트 `install/wNN_<차시>.sh`는 여러 번 실행해도 결과가 같다(멱등). 늦게 합류한 수강생을 위해 전체를 한 번에 설치하는 `install/all.sh`와 `environment.yml`도 둔다.
- **점검 명령**: `dtlab check-env --week N`은 N주차까지 필요한 도구를 확인한다. 빠진 항목은 설치 스크립트 이름과 함께 알려 준다. 1주차에는 대부분이 「아직 설치 안 됨(예정 주차 표시)」으로 나오고, 주차가 지날수록 목록이 채워진다. 이것도 진행 상황 표시 역할을 한다.
- **지원 환경**
  - Linux(Ubuntu 22.04 이상) 권장
  - Windows는 WSL2 Ubuntu
  - macOS는 conda 경로만 지원하고, 소스 빌드는 Homebrew 컴파일러로 한다.
- **버전 기록**: 설치할 때 버전을 `env/versions.lock`에 남긴다. LAMMPS는 저장소를 만드는 시점의 stable 태그로 고정한다.

### 8.3 LAMMPS 빌드 명세 (4-1 · 8-4)

```bash
# 4-1: CPU 전용 빌드 — install/w04_4-1_lammps.sh
git clone -b stable_22Jul2025_update6 --depth 1 https://github.com/lammps/lammps.git   # 선택 실습 — 기본은 conda-forge 판
cmake -S lammps/cmake -B build-lmp -D CMAKE_BUILD_TYPE=Release \
  -D BUILD_MPI=on -D BUILD_OMP=on -D LAMMPS_EXCEPTIONS=on \
  -D PKG_MOLECULE=on -D PKG_KSPACE=on -D PKG_RIGID=on -D PKG_EXTRA-MOLECULE=on \
  -D PKG_EXTRA-FIX=on -D PKG_EXTRA-DUMP=on -D PKG_MISC=on -D PKG_MANYBODY=on \
  -D PKG_OPENMP=on -D PKG_REAXFF=on -D FFT=FFTW3
cmake --build build-lmp -j 8 && cmake --install build-lmp --prefix $CONDA_PREFIX
# 8-4: (소스 빌드를 쓸 때만) ML-SNAP 추가 재빌드 — conda-forge 판에는 이미 포함 — install/w08_8-4_lammps_ml.sh
cmake -B build-lmp -D PKG_ML-SNAP=on && cmake --build build-lmp -j 8 && cmake --install build-lmp --prefix $CONDA_PREFIX
```

- 설치 스크립트는 `lmp -h`의 패키지 목록을 `env/versions.lock`에 기록하고, 빠진 패키지가 있으면 실패로 끝낸다(fail-closed).
- 빌드가 실패하면 conda-forge 미리 빌드판으로 계속 진행할 수 있다. 다만 벤치마크 결과는 판별로 따로 기록한다.

### 8.4 덱 수정이 필요한 곳
- **4-1** 「GPU/KOKKOS 빌드」 → 「CPU(MPI · OpenMP) 빌드 실습, GPU · KOKKOS는 개념만」. 강의계획서 차시 내용 문구와도 차이가 생기므로, 강의계획서 수정 여부를 함께 판단해야 한다.
- **4-4** Moltemplate는 비교용으로만 소개하고, 실습 경로는 RDKit + Packmol + dtlab.
- **8-4** ML 퍼텐셜 실습은 SNAP(CPU)으로 한다. MACE · NequIP 같은 등변 신경망 퍼텐셜은 개념과 비교만 다룬다.
- **12-3** 기본 백엔드는 SQLite이고, PostgreSQL은 같은 스키마를 옮기는 선택 실습으로 둔다.

## 9. 한계 (README에 명시)

- 단순 분자 4종 바인더는 실제 아스팔트의 점탄성 · 상분리를 재현하지 않는다. **조건 사이 상대 경향을 학습하는 교육용 모델**이다.
- 인장 속도가 실험보다 수 자릿수 빠르고 셀이 작다. σ_max 절댓값은 실험 인장강도와 비교하지 않는다.
- ClayFF 결정을 고정했으므로 광물 내부 변형은 없다. 파괴는 계면 또는 바인더 내부에서만 생긴다.
- MD-TSR은 AASHTO T 283 TSR의 분자 수준 대응 지표일 뿐이며 규격 판정에 쓰지 않는다.
- 온도당 약 100개는 작은 데이터다. 모델 오차는 반복 실행으로 추정한 시드 산포 하한과 함께 보고한다.
