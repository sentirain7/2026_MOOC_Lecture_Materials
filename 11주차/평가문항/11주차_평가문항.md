# 11주차 평가문항 — 문헌 고찰 — Obsidian 기반 문헌 검색·관리와 자동 스크래핑

문항 6개. 문항마다 유형 · 난이도 · 차시 · 정답 · 해설 · 근거 슬라이드를 적었다. 원본 데이터는 같은 폴더의 `q11.json`.

## 1. (객관식 · 난이도 하 · 차시 11-1)

불리언 검색식(Boolean query)을 조립하는 규칙으로 옳은 것은?

① 개념 블록끼리는 OR, 괄호 안 동의어끼리는 AND로 잇는다  
② 괄호 안 동의어는 OR, 개념 블록끼리는 AND로 잇는다  
③ 동의어 누락을 줄이려면 모든 검색어를 AND로 잇는다  
④ 결과 편수를 늘리려면 동의어를 NOT으로 묶는다  

- **정답**: ② 괄호 안 동의어는 OR, 개념 블록끼리는 AND로 잇는다
- **해설**: 괄호 안의 동의어·인접 개념은 OR로 묶어 범위를 넓히고, 재료·방법·성분·물성 같은 개념 블록끼리는 AND로 이어 교차 조건을 만든다. 모든 검색어를 AND로 이으면 동의어를 오히려 놓치고, NOT은 특정 주제를 배제할 때 쓰므로 편수를 줄인다.
- **근거 슬라이드**: 6번 「검색 전략」

## 2. (OX · 난이도 하 · 차시 11-1)

문헌 조사도 재현성(reproducibility) 확보 대상이므로 검색원·질의·기간·포함 및 배제 기준·결과 건수·한계를 함께 기록해야 한다.

- **정답**: O
- **해설**: 검색원·질의 수·기간·포함·배제 기준·결과 건수·한계 가운데 한 항목이라도 빠지면 같은 검색 결과를 다시 만들 수 없다. 그래서 검색식과 실행 날짜, 결과 건수를 반드시 함께 기록한다.
- **근거 슬라이드**: 8번 「검색 기록 사례」

## 3. (객관식 · 난이도 중 · 차시 11-2)

Obsidian에서 백링크(backlink)의 기능으로 옳은 것은?

① 노트 이름을 [[ ]]로 감싸 다른 노트로 가는 링크를 만든다  
② YAML 속성 값을 기준으로 노트를 표로 모아 보여 준다  
③ 링크가 하나도 없는 고아 노트를 찾아 색으로 표시한다  
④ 현재 노트를 가리키는 다른 노트의 목록을 자동으로 보여 준다  

- **정답**: ④ 현재 노트를 가리키는 다른 노트의 목록을 자동으로 보여 준다
- **해설**: 백링크는 현재 노트를 가리키는 노트 목록을 자동으로 보여 주는 기능으로, 이름만 언급된 노트도 따로 표시한다. [[ ]]로 링크를 만드는 것은 위키링크(wikilink), 속성 기반 표는 Dataview 플러그인, 고아 노트(orphan) 탐색은 그래프 뷰의 필터 기능이다.
- **근거 슬라이드**: 15번 「Obsidian 기본 구조」

## 4. (단답형 · 난이도 중 · 차시 11-3)

여러 수집 폴더의 문헌 중복을 제거할 때 앞뒤 공백·끝 마침표와 URL 접두를 지우고 소문자로 바꾸는 정규화를 거쳐 고유 키로 쓰는 문헌 식별자는?

- **정답**: DOI (인정: DOI · doi · 디지털 객체 식별자 · Digital Object Identifier · DOI(디지털 객체 식별자))
- **해설**: 같은 논문이 폴더마다 다른 표기로 들어오므로 DOI(digital object identifier)를 정규화해 고유 키로 쓴다. DOI는 대소문자를 구분하지 않아 소문자 변환이 가능하며, DOI가 없으면 PII, 그것도 없으면 제목을 키로 쓴다.
- **근거 슬라이드**: 21번 「중복 제거 · 라이브」

## 5. (객관식 · 난이도 상 · 차시 11-3)

LLM 구조화 추출 결과 force_field 필드에서 같은 힘장이 「COMPASS II」「COMPASSII」「COMPASS-II」처럼 여러 표기로 흩어져 있고, 값이 없는 경우는 문자열 「None」으로 기록되었다. 힘장별 편수를 집계하기 전 조치로 가장 적절한 것은?

① 표준 이름 사전으로 표기를 매핑하고 「None」을 null로 통일한다  
② 원문 표기를 그대로 보존해 표기별 편수를 따로 집계한다  
③ 필드 채움률이 높으므로 추출 정확도가 충분하다고 보고 집계한다  
④ 「None」을 하나의 힘장 범주로 두고 가장 많은 표기만 남긴다  

- **정답**: ① 표준 이름 사전으로 표기를 매핑하고 「None」을 null로 통일한다
- **해설**: 추출 직후 표준 이름(canonical name) 사전 매핑과 null 통일을 한 뒤에 집계해야 하며, 정규화 전 집계는 금지한다. 표기별로 그대로 세면 COMPASS II가 과소 집계되고, 「None」 문자열은 None이라는 힘장으로 잘못 세어진다. 채움률은 값이 적힌 비율일 뿐 정확도를 뜻하지 않는다.
- **근거 슬라이드**: 25번 「추출 결과 · 필드 정규화」

## 6. (OX · 난이도 중 · 차시 11-4)

Better BibTeX 자동 내보내기로 만든 .bib 파일은 LaTeX 전용이므로, Pandoc 마크다운 원고와 Obsidian 노트는 서지 파일을 따로 관리해야 한다.

- **정답**: X
- **해설**: 틀린 설명이다. Better BibTeX는 라이브러리가 바뀔 때마다 .bib 파일을 자동으로 다시 쓰며, LaTeX·Pandoc·Obsidian이 같은 .bib 파일을 참조한다. 고정(pin)된 인용키(citation key) 하나로 서지·노트·원고를 연결하는 것이 핵심이다.
- **근거 슬라이드**: 29번 「Zotero 수집과 인용키」
