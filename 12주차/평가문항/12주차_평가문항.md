# 12주차 평가문항 — 자율 탐색 파이프라인 (1) — 파이프라인 구조와 데이터 큐레이션

문항 6개. 문항마다 유형 · 난이도 · 차시 · 정답 · 해설 · 근거 슬라이드를 적었다. 원본 데이터는 같은 폴더의 `q12.json`.

## 1. (OX · 난이도 하 · 차시 12-1)

자율 탐색 파이프라인에서 ML 대리모델은 LAMMPS 로그를 직접 읽지 않고, 로그 파싱과 평균 ± 표준오차 계산을 거쳐 적재된 구조화 데이터베이스를 읽는다.

- **정답**: O
- **해설**: 실험 한 건은 LAMMPS → 로그 파싱 → 평균 ± SE → 구조화 DB 순으로 흐르고, 9주차 XGBoost+SHAP과 10주차 GNN 대리모델은 이 구조화 DB를 읽는다. ML 코드가 로그를 직접 읽으면 파싱 규칙이 바뀔 때마다 학습 코드도 고쳐야 한다.
- **근거 슬라이드**: 8번 「실제 플랫폼 구조」

## 2. (객관식 · 난이도 중 · 차시 12-2)

Li & Greenfield 골격 분자에 치환 레버(lever)를 적용한 직후 SARA 역할 검사를 하는 이유로 옳은 것은?

① 치환 후 분자량이 계산 가능한 범위를 넘는지 확인하기 위해  
② 레버 값이 정수인지 확인해 격자점 수를 줄이기 위해  
③ 첨가제 라이브러리에 힘장 조합이 적혀 있는지 보기 위해  
④ 치환된 분자가 원래 SARA 분류의 구조 조건을 벗어날 수 있어서  

- **정답**: ④ 치환된 분자가 원래 SARA 분류의 구조 조건을 벗어날 수 있어서
- **해설**: 치환으로 분자가 원래 SARA 분류의 구조 조건을 벗어날 수 있으므로, 예를 들어 아스팔텐은 다환방향족 + 헤테로원자 + 알킬곁사슬을 갖췄는지 검사하고 불통과 조합은 후보에서 뺀다. 레버가 분자량만 바꾼다고 보는 것은 오해이며, 힘장 표시 확인은 첨가제 라이브러리 단계의 일이다.
- **근거 슬라이드**: 11번 「구조 치환 레버」

## 3. (단답형 · 난이도 하 · 차시 12-3)

조성·실행·물성 테이블 설계에서 밀도·점도·CED 같은 물성을 열(column)이 아니라 「exp_id, 물성명, 값」 행(row)으로 저장해, 새 물성이 생겨도 스키마를 바꾸지 않게 하는 저장 형식의 명칭은?

- **정답**: 긴 형식 (인정: 긴 형식 · long format · 롱 포맷 · long 형식 · 긴 형식(long format) · 롱 형식)
- **해설**: 물성을 행으로 두는 긴 형식(long format)은 새 물성이 생겨도 행만 추가하면 되므로 테이블 구조를 바꿀 필요가 없다. 학습에 필요한 넓은 표는 학습 직전에 피벗(pivot)으로 펼치며, 저장 형식과 학습 형식을 구분하는 것이 핵심이다.
- **근거 슬라이드**: 14번 「스키마 설계」

## 4. (객관식 · 난이도 중 · 차시 12-3)

fail-closed 적재 계약(contract)에서 레지스트리(registry)에 등록되지 않은 물성 이름(예: visc)이나 정의와 다른 단위의 값이 들어올 때의 처리로 옳은 것은?

① 저장을 거부하고 오류로 처리한다  
② 경고만 기록하고 값은 그대로 저장한다  
③ 가장 비슷한 등록 이름으로 바꿔 저장한다  
④ metadata_json 안에 임시 태그로 저장한다  

- **정답**: ① 저장을 거부하고 오류로 처리한다
- **해설**: fail-closed 저장은 규칙을 어기면 닫히는 쪽으로 동작하므로, 레지스트리에 없는 물성 이름이나 정의와 다른 단위는 저장을 거부한다. 경고만 띄우는 방식은 결국 아무도 경고를 읽지 않게 되고, metadata_json에는 사람 메모·디버깅 정보·임시 태그만 둔다.
- **근거 슬라이드**: 16번 「PostgreSQL 적재 계약」

## 5. (OX · 난이도 중 · 차시 12-4)

코드의 git 커밋 해시와 난수 시드만 고정하면, 그사이 데이터베이스가 백필(backfill)이나 NULL 정정으로 바뀌어도 같은 학습 결과를 재현할 수 있다.

- **정답**: X
- **해설**: 틀린 설명이다. 재현성을 위해서는 코드(git 해시·환경 파일), 데이터(스냅샷 해시·폴드 인덱스), 모델(체크포인트·하이퍼파라미터·시드), 실행(LAMMPS 버전·힘장 파일·입력 해시) 네 가지를 함께 고정해야 한다. 코드와 시드를 고정해도 DB가 바뀌면 같은 결과가 나오지 않으므로 데이터 스냅샷을 매니페스트(manifest)에 남긴다.
- **근거 슬라이드**: 20번 「재현성」

## 6. (객관식 · 난이도 상 · 차시 12-4)

점도를 구하는 전단 런에서 체적탄성률이 물리적으로 불가능하게 큰 값으로 저장되었고, 원인은 NPT 구간이 없어 부피 분산 var(V)가 0에 가까워진 것으로 확인되었다. 가장 적절한 처리는?

① 평균 ± 3σ 밖의 값을 통계적으로 제거하고 계산 절차는 유지한다  
② 해당 전단 런의 밀도·점도를 포함한 모든 결과를 삭제한다  
③ NPT 구간이 없으면 계산하지 않게 하고 물리 범위 게이트를 둔다  
④ 로그 변환으로 값의 범위를 줄인 뒤 학습 데이터에 포함한다  

- **정답**: ③ NPT 구간이 없으면 계산하지 않게 하고 물리 범위 게이트를 둔다
- **해설**: 원인이 값이 아니라 계산 조건이므로 계산 진입 조건(NPT 없으면 계산 안 함)과 물리 범위 게이트의 이중 방어로 처리한다. 통계적 제거는 원인이 남아 다음 계산에서 다시 나오며, 같은 런의 밀도·MSD·점도는 유효하므로 런 전체를 버리지 않는다.
- **근거 슬라이드**: 19번 「이상치 사례」
