# 지시문 사용 환경 · 「만들어 보기」 장의 Claude Code 지시

덱의 「만들어 보기」 장에는 번호가 붙은 지시문(P주차-순번, 예 P1-1)이 있다. 저장소가 코드 · 입력 파일을 주고, 지시문은 Claude Code 가 그 파일로 할 일을 정한다. 이 강좌의 기본 환경은 **저장소 폴더에서 실행한 Claude Code** 다(`docs/claude_code_quickstart.md`).

## 1. 필요한 것
| 항목 | 내용 |
|---|---|
| Claude Code | 터미널의 `claude` · 유료 요금제(Pro 이상) 또는 Console(API) 계정 |
| 강좌 환경 | conda `mdai` (`environment.yml`) |
| 저장소 폴더 | `weekNN/` 에서 `claude` 를 연다 · 저장소 맨 위의 `CLAUDE.md`(강좌 규칙)를 Claude Code 가 자동으로 읽는다 |

## 2. 순서 (지시문 1개 = 대화 1개 · 앞 작업과 주제가 다르면 `/clear`)
1. 덱의 지시 상자에서 **「복사」** (또는 `weekNN/prompts.md`).
2. Claude Code 입력창에 **붙여 넣기** → **대괄호 [ ] 안만** 바꾼다(재료명 · 조건 · 파일 이름).
3. 파일은 붙여 넣지 않는다. 지시문의 `@경로` 로 Claude Code 가 직접 읽는다.
4. 명령 실행 · 파일 수정 승인 창이 뜨면 무엇을 하는지 읽고 승인한다.
5. 결과는 Claude Code 가 **`weekNN/out/P주차-순번_result.md`** 로 저장한다(CLAUDE.md 규칙).
6. 덱 장 아래의 **확인 포인트 2개**를 통과했는지 본다. 통과하지 못하면 같은 대화에서 「~을 고쳐라」.

## 3. 규칙 3
- **번호 없는 지시는 결과로 제출하지 않는다.** 결과 파일 이름 = 지시문 번호. 제출 · 다음 주 입력 · W16 기록의 기준이 된다.
- **받은 수치의 「확인 필요」 표시를 지우지 않는다.** 모델이 낸 숫자는 초안이다. 이 강좌에서 수치의 근거는 W09 · W10 의 계산과 실험뿐이다.
- **강좌 스크립트(`scripts/`)는 기준 코드다.** Claude Code 가 고치자고 하면 거절하고, 변형은 `out/` 아래 새 파일로 만들게 한다.

## 4. 문제 해결
| 증상 | 조치 |
|---|---|
| 답이 길고 표가 없다 | 「표만 다시, 설명 없이」 |
| 수치에 근거가 없다 | 「근거가 없는 값은 확인 필요로 표시하고 출처를 적어라」 |
| 원하지 않는 파일 수정 | Esc 로 멈춤 → Esc 두 번 · 되돌리기 · 또는 `git checkout -- 파일` |
| 코드가 저장소와 다르게 동작 | 「강좌 스크립트를 기준으로, 두 코드의 차이와 결과가 다른 이유를 표로」 |
| 대화가 길어져 답이 흐려짐 | `/clear` 후 지시문부터 다시 |

## 5. (선택) 채팅형 LLM 으로 쓸 때 · 이전 안내

Claude Code 를 쓸 수 없는 경우의 이전 안내(브라우저 채팅창에 붙여 넣기)를 그대로 남긴다.


덱의 「만들어 보기」 장에는 번호가 붙은 프롬프트(P주차-순번, 예 P1-1)가 있다. 저장소가 코드 · 입력 파일을 주고, 프롬프트는 그것을 **내 재료 · 내 환경에 맞게 바꾸거나 결과를 해석**하는 데 쓴다.

### 1. 필요한 것
| 항목 | 내용 |
|---|---|
| LLM 채팅 계정 1개 | Claude.ai · ChatGPT · Gemini 중 하나 · 무료 계정이면 된다 · 설치 없음 |
| 브라우저 | 채팅창 + 덱(단독 실행 HTML) 을 나란히 연다 |
| 저장소 폴더 | 결과 파일을 `weekNN/out/` 에 저장한다 (Colab 이면 노트북의 파일 패널에 업로드) |
| 선택 | Claude Code(터미널): 저장소 폴더에서 실행하면 파일을 직접 읽고 쓴다. 프롬프트 앞에 「저장소 루트는 현재 폴더다」 한 줄을 붙인다 |

### 2. 순서 (프롬프트 1개 = 새 대화 1개)
1. 덱의 프롬프트 상자에서 **「복사」** 버튼 (또는 `weekNN/prompts.md` 에서 복사).
2. 채팅창에 **붙여 넣기** (Ctrl+V · macOS ⌘V).
3. **대괄호 [ ] 안만** 바꾼다 — 재료명 · 운영체제 · 파일 이름. 나머지 문장은 그대로.
4. 파일 내용을 물어야 하는 프롬프트(예 P1-2 의 setup_report.json)는 **파일 본문을 프롬프트 맨 끝에 붙여 넣는다**. 채팅창의 파일 첨부 기능을 써도 된다.
5. 전송 → 받은 표 · 코드를 **`weekNN/out/P주차-순번_result.md`** 로 저장한다 (예 `week01/out/P1-1_result.md`).
6. 덱 장 아래의 **확인 포인트 2개**를 통과했는지 본다. 통과하지 못하면 「~을 고쳐라」로 같은 대화에서 다시 묻는다.

### 3. 규칙 3
- **번호 없는 프롬프트는 쓰지 않는다.** 결과 파일 이름 = 프롬프트 번호. 제출 · 다음 주 입력 · W16 기록의 기준이 된다.
- **받은 수치의 「확인 필요」 표시를 지우지 않는다.** LLM 의 숫자는 초안이다. 이 강좌에서 수치의 근거는 W09 · W10 의 계산과 실험뿐이다.
- **받은 코드는 저장소 스크립트와 비교한다.** 저장소 스크립트가 기준이고, LLM 코드는 매개변수를 바꾼 변형으로만 쓴다. 다른 결과가 나오면 저장소 스크립트 결과를 제출한다.

### 4. 문제 해결
| 증상 | 조치 |
|---|---|
| 답이 길고 표가 없다 | 「표만 다시, 설명 없이」 |
| 수치에 근거가 없다 | 「근거가 없는 값은 확인 필요로 표시하고 출처를 적어라」 |
| 내 운영체제와 다른 명령 | 대괄호의 운영체제를 고쳐 다시 전송 (Windows 는 WSL2 Ubuntu 로) |
| 코드가 저장소와 다르게 동작 | 저장소 스크립트를 기준으로 하고 차이만 물어본다: 「이 두 코드의 차이와 결과가 다른 이유」 |
| 대화가 길어져 답이 흐려짐 | 새 대화에서 프롬프트부터 다시 |
